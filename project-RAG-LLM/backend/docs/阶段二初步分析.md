
### Step 1：`embedding_service.py` 瘦身（高价值，低风险）

**改法：保留文件，替换实现，大幅瘦身。**

```python
# services/embedding_service.py（重构后，约 20 行）
from langchain_openai import OpenAIEmbeddings
from .. import config

_embeddings: OpenAIEmbeddings | None = None

def get_embeddings() -> OpenAIEmbeddings:
    """获取全局共享的 Embeddings 实例（懒加载单例）。"""
    global _embeddings
    if _embeddings is None:
        _embeddings = OpenAIEmbeddings(
            model=config.EMBEDDING_MODEL_NAME,
            openai_api_key=config.DASHSCOPE_API_KEY,
            openai_api_base=config.EMBEDDING_API_BASE_URL,
            dimensions=config.EMBEDDING_DIMENSION,
            chunk_size=config.EMBEDDING_BATCH_SIZE,
        )
    return _embeddings
```

**收益**：
- 删除 `EmbeddingService` 类（200+ 行手搓 API 调用代码）
- 删除 `LCEmbeddingAdapter`（10 行适配器，因为 `OpenAIEmbeddings` 直接实现 LangChain `Embeddings` 接口）
- `rag_agent.py` 和 `ingest_data.py` 都改为 `from ..services.embedding_service import get_embeddings`，调用方式统一

### Step 2：抽取 `tools/` 包（高工程价值）

当前 Tool 用**闭包**定义，捕获 `retriever`、`use_web_search`、`search_state` 等变量：
- 闭包内 `search_state` 是可变 dict → 潜在 race condition
- Tool 耦合在 `_create_dynamic_agent` 内部 → 无法独立测试
- RAG 和 Web Search 混在同一个 Tool → Agent 无法独立选择

**改法：创建 `app/tools/` 包，每个 Tool 是独立的工厂函数。**

```python
# tools/retriever_tool.py
from langchain.tools.retriever import create_retriever_tool
from langchain_core.retrievers import BaseRetriever
from langchain_core.tools import BaseTool

def build_retriever_tool(retriever: BaseRetriever) -> BaseTool:
    return create_retriever_tool(
        retriever=retriever,
        name="search_knowledge_base",
        description="从课程知识库检索相关笔记和文档。优先用于课程内容相关问题。",
    )
```

```python
# tools/web_search_tool.py
from langchain_core.tools import tool
from ..services.web_search_service import WebSearchService
from .. import config

def build_web_search_tool(service: WebSearchService):
    @tool("web_search")
    def web_search(query: str) -> str:
        """搜索互联网获取最新信息。用于知识库未覆盖或需要实时数据的问题。"""
        results = service.search(query, max_results=config.WEB_SEARCH_RESULT_LIMIT)
        return "\n\n".join(
            f"标题: {r['title']}\n来源: {r['url']}\n内容: {r['snippet']}"
            for r in results
        )
    return web_search
```

**收益**：
- Tool 可独立测试（传入 mock retriever / service）
- `rag_agent.py` 只需 `import` 并组合
- RAG 与 Web Search 解耦，Agent 可选择性调用

### Step 4：`rag_agent.py` 重构 + LangGraph API 升级（依赖前三步）

**同时完成两个目标**：
1. 重构为组装函数（依赖 Step 1-3 的成果）
2. 替换 API：`langchain.agents.create_agent` → `langgraph.prebuilt.create_react_agent`

**为什么在这里升级 LangGraph**：
- ✅ Step 1-3 已完成职责分离，`rag_agent.py` 变成纯组装函数
- ✅ 此时替换 API 风险最低（只改一个函数）
- ✅ 避免重复工作（不会在 Step 4 重构后再次改 API）
- ✅ 为 Phase 3 的多 Agent 系统打好基础

前三步完成后，`rag_agent.py` 的 `_create_dynamic_agent` 变成干净的组装函数：

```python
# core/rag_agent.py（重构后，约 80 行）
from langgraph.prebuilt import create_react_agent  # 新 API
from ..services.embedding_service import get_embeddings
from ..services.retriever_service import build_retriever
from ..tools.retriever_tool import build_retriever_tool
from ..tools.web_search_tool import build_web_search_tool
from ..prompts import RAG_SYSTEM_PROMPT
from .checkpointer import get_checkpointer

def _create_agent(session_id, temperature, top_k, messages_to_keep, max_tokens, use_web_search, llm_model):
    """纯组装函数：从各服务取组件，组合成 Agent。不包含任何业务逻辑。"""
    llm = LLMHandler.get_instance().get_llm(...)
    retriever = build_retriever(session_id, top_k, get_embeddings())
    tools = [build_retriever_tool(retriever)]
    if use_web_search:
        tools.append(build_web_search_tool(WebSearchService.get_instance()))

    # 关键：同时完成重构 + API 替换
    return create_react_agent(
        llm,
        tools,
        state_modifier=RAG_SYSTEM_PROMPT,  # 注意：参数名从 prompt 改为 state_modifier
        checkpointer=get_checkpointer()
    )
```

**关键差异**（基于 2026 最新文档）：
- `create_agent` (LangChain): 简单的 Agent 包装器，流式支持有限
- `create_react_agent` (LangGraph): 基于 StateGraph 的 ReAct Agent，原生支持：
  - ✅ 更好的流式输出（`stream_mode="messages"`）
  - ✅ 原生 checkpointer 集成（无需 Middleware 包装）
  - ✅ 状态管理和中断恢复
  - ✅ 更灵活的 Tool 调用控制

**API 对比**：
```python
# 旧 API (当前)
from langchain.agents import create_agent
agent = create_agent(llm, tools, prompt=system_prompt, checkpointer=checkpointer)

# 新 API (目标)
from langgraph.prebuilt import create_react_agent
agent = create_react_agent(llm, tools, state_modifier=system_prompt, checkpointer=checkpointer)
```

**注意**：`state_modifier` 参数替代了 `prompt`，支持更灵活的状态修改。

### Step 5：retriever 增强（可选，Phase 2 后期）

```python
# services/retriever_service.py
from langchain.retrievers.multi_query import MultiQueryRetriever

def build_retriever(session_id, top_k, embeddings, llm=None):
    base = vector_repo.as_langchain_retriever(embeddings, search_kwargs={
        "k": top_k,
        "filter": {"$or": [{"session_id": "system"}, {"session_id": session_id}]}
    })
    if llm:  # 启用 MultiQueryRetriever
        return MultiQueryRetriever.from_llm(retriever=base, llm=llm, include_original=True)
    return base
```

**注意**：`MultiQueryRetriever` 每次查询额外调用一次 LLM 生成变体 query，会增加延迟和费用，需测试后决定是否默认开启。

### Step 7：文档处理小改进（低优先级）

**验证结果**：
- ✅ `DirectoryLoader` **确实不适用**：项目是单文件上传场景（`document.py` 的 `/upload` 端点）
- ✅ 当前 `document_ingest_service.py:48-75` 的 Loader 选择逻辑合理，保留即可
- ⚠️ **调参建议**：
  - `chunk_size=500 → 800`（当前对中文长文档过于保守）
  - `chunk_overlap=50 → 150`（提高上下文连续性）
  - 理由：中文字符密度高，500 字符约 250 个汉字，对技术文档偏小
- 🔬 `SemanticChunker`：实验性功能，需要额外的 embedding 调用，成本较高，暂不推荐
